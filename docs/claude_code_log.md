# Claude Code 활용 기록

README의 "Claude Code 활용 기록" 섹션 원본. Phase마다 **무엇을 요청했고 → Claude Code가 무엇을 만들었고 → 어떻게 검증했고 → 무엇을 고쳤는지**를 남긴다.

## Phase 1. 데이터 생성·검증

**요청**: 5개 테이블(departments/employees/workload/skills/staffing_plan) 합성 데이터 생성, 계절성·조직별 특성·스킬 불균형 반영, assert 기반 검증 자동화.

**Claude Code가 만든 것**
- `src/data_gen.py` — seed 고정 생성기, CSV + SQLite 저장
- `src/validate.py` — 7개 무결성 검증 함수 (CLI와 pytest가 같은 함수 사용)
- `tests/test_data.py` — 14개 테스트
- `docs/data_generation.md`

**설계 판단**
- 생성기의 "숨은 정답"(조직별 필요 FTE·성장률)을 테이블에 저장하지 않고, 저장 컬럼을 스키마로 고정해 검증한다. 나중에 예측 모델이 정답을 몰래 참조하는 일을 구조적으로 막기 위함.
- 정원(TO)을 "직전 연말 현원 + 부서 요청분"으로 생성해, 문제 정의("과거 정원·부서 요청에만 의존한 인력계획")를 데이터 자체에 재현했다.

**검증 방법**
1. `python -m src.validate` — 7개 검증 모두 PASS
2. `pytest` — 14 passed
3. **검증 함수 자체를 검증**: 데이터를 일부러 망가뜨려(존재하지 않는 부서 D99, 2026-10 미래 행, 숨은 컬럼 추가, 현원 +1) 검증이 실제로 실패하는지 테스트. "항상 PASS만 나오는 검증"을 피하기 위함.
4. 생성 결과가 의도한 시나리오대로 나왔는지 요약 통계로 확인:
   - 최근 12개월 업무부하(필요 FTE / 현원): AI서비스팀 1.22, 클라우드 1.13 (과부하) / 경영지원 0.87, SI2 0.90 (저활용) — 의도와 일치
   - 월별 업무량 지수: 3·6·9월 1.07~1.09, 1월 0.94 — 분기말 계절성 반영 확인

**발견·수정한 문제**
- `load()`가 테이블명을 f-string으로 SQL에 넣고 있었음 → 테이블명은 파라미터 바인딩이 불가능하므로 스키마 화이트리스트로 제한하도록 수정 (SQL 인젝션 여지 제거).
- Windows 콘솔(cp949)에서 한글 출력이 깨짐 → 파일(CSV는 utf-8-sig, SQLite)은 정상임을 확인. 콘솔 출력 시 `PYTHONIOENCODING=utf-8` 사용.
- 부하율 계산 시 `current_headcount`에 휴직자(8명)가 포함됨을 확인 → Phase 2 KPI에서는 가용 인원(active)으로 계산하기로 결정.

## Phase 2. Module A — 조직 생산성 진단

**요청**: 조직별 현원, 1인당 처리량, 업무부하율, 초과근무 추정치 KPI와 시각화.

**Claude Code가 만든 것**
- `src/kpi.py` — 월별 KPI(`monthly_metrics`)와 최근 12개월 스냅샷(`department_kpis`)
- `tests/test_kpi.py` — 6개 테스트
- `notebooks/analysis.ipynb` Module A 섹션, 차트 3장(`docs/images/a_*.png`)
- `docs/methodology.md` Module A 섹션

**설계 판단**
- 부하율은 월별 비율의 단순 평균이 아니라 **12개월 필요시간 합 / 가용시간 합**으로 계산. 업무량이 많은 분기말 달이 결과에 더 크게 반영되도록.
- 가용인원은 현원이 아니라 **active 인원**(휴직자 제외) 기준 — Phase 1에서 발견한 문제를 반영.
- 1인당 처리량은 조직마다 '1건'의 크기가 달라(2.5h~40h) 조직 간 비교에 쓰지 않는다고 문서에 명시.

**검증 방법**
1. **손으로 계산 가능한 최소 데이터로 공식 검증**: 10명 × 140h = 1,400h, 100건 × 14h = 1,400h → 부하율 정확히 1.0. 120건이면 1.2, 1인당 초과 28h. 휴직 2명이면 1,400 / 1,120 = 1.25. 테스트로 고정.
2. 경계값 테스트: 부하율 1.05는 '적정', 1.06은 '과부하'.
3. 합성 데이터 시나리오 일치 확인: AI·클라우드는 과부하, SI2·경영지원은 저활용으로 분류되는지 테스트.
4. 차트를 이미지로 직접 열어 한글 폰트·라벨 겹침 확인.

**발견·수정한 문제**
- Phase 1 점검 때 AI서비스팀 부하율이 1.22였는데 KPI 모듈에서는 1.37 → 오류인지 확인. Phase 1 점검은 "12개월 필요 FTE / **현재** 현원"이었고, KPI는 **각 월의 그 당시 현원**(AI팀은 1년 전 20명대 초반)과 휴직자 제외를 반영한 값이라 차이가 정상임을 확인. 계산 기준을 methodology.md에 명시.
- 현원·정원·필요 FTE 비교 차트에서 **값이 같은 점이 서로 가려짐**(클라우드: 현원 = 정원 = 38) → 현원을 속이 빈 큰 원으로 바꿔 겹쳐도 보이게 수정.
- 노트북 실행 시 Jupyter 커널이 응답하지 않음(커널 프로세스는 뜨지만 클라이언트 연결 실패, ipykernel 7.x → 6.29.5로 바꿔도 동일). 로컬 환경 문제로 판단하고, 커널 없이 IPython으로 in-process 실행해 출력을 저장하는 방식으로 우회.
